# App de Rotina para Casal — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the foundation of the app — PWA project scaffold, Supabase schema with RLS, auth, and couple pairing — so a signed-up user can log in and link with their partner.

**Architecture:** React + TypeScript + Vite PWA (installable on Android/iOS home screen via `vite-plugin-pwa`), backed by Supabase (Postgres + Auth + Realtime + Row Level Security). Local Supabase dev stack (via the Supabase CLI + Docker) is used for schema migrations and RLS integration tests before pushing to the hosted free-tier project.

**Tech Stack:** React 18, TypeScript, Vite, vite-plugin-pwa, Supabase JS v2, Supabase CLI, Vitest, @testing-library/react.

This is **Plan 1 of 4** for the full spec (`docs/superpowers/specs/2026-08-12-app-rotina-casal-design.md`). Follow-on plans (not yet written): Plan 2 — Categories & Routine Items CRUD + recurrence engine; Plan 3 — Hoje/Agenda/Estatísticas screens; Plan 4 — Push notifications.

## Global Constraints

- Frontend must be an installable PWA that works on both Android and iPhone home screens (spec §Arquitetura).
- Backend is Supabase: Postgres + Auth (email/senha) + Realtime + RLS (spec §Arquitetura, §Decisões de escopo).
- No paid services — everything must run on Supabase's free tier (spec §Contexto e objetivo).
- Each new account gets 4 default categories: Treino/Saúde, Estudos, Trabalho, Lazer — user can add/edit/remove more (spec §Decisões de escopo).
- `item_completions` tracks completion **per user**, even for shared items (spec §Decisões de escopo).
- Items with `is_shared = true` are editable/deletable by either partner; personal items only by their owner (spec §Modelo de dados).
- Auth is email + password via Supabase Auth (spec §Decisões de escopo).

`supabase/migrations/0001_init_schema.sql`:

```sql
create extension if not exists pgcrypto;

-- Couples: links two auth users together
create table couples (
  id uuid primary key default gen_random_uuid(),
  code text unique not null,
  user_a uuid not null references auth.users(id) on delete cascade,
  user_b uuid references auth.users(id) on delete cascade,
  created_at timestamptz not null default now()
);

create table categories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  nome text not null,
  cor text not null default '#6366f1',
  icone text not null default 'circle',
  created_at timestamptz not null default now()
);

create table routine_items (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  category_id uuid not null references categories(id) on delete cascade,
  titulo text not null,
  notas text,
  prioridade text not null default 'media' check (prioridade in ('alta', 'media', 'baixa')),
  data_inicio date not null,
  horario time not null,
  is_shared boolean not null default false,
  recurrence_rule jsonb not null default '{"type":"none"}'::jsonb,
  recurrence_end jsonb,
  created_at timestamptz not null default now()
);

create table item_completions (
  id uuid primary key default gen_random_uuid(),
  routine_item_id uuid not null references routine_items(id) on delete cascade,
  user_id uuid not null references auth.users(id) on delete cascade,
  data date not null,
  completed_at timestamptz not null default now(),
  unique (routine_item_id, user_id, data)
);

create table push_subscriptions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  subscription_json jsonb not null,
  created_at timestamptz not null default now()
);

-- Returns the partner's user id for a given user, if they're in a couple.
create or replace function partner_id(uid uuid)
returns uuid
language sql
stable
as $$
  select case
    when user_a = uid then user_b
    when user_b = uid then user_a
    else null
  end
  from couples
  where user_a = uid or user_b = uid
  limit 1;
$$;

-- couples
alter table couples enable row level security;

create policy "select own or joinable couples"
on couples for select
using (user_a = auth.uid() or user_b = auth.uid() or user_b is null);

create policy "insert own couple"
on couples for insert
with check (user_a = auth.uid());

create policy "join couple"
on couples for update
using (user_b is null and user_a <> auth.uid())
with check (user_b = auth.uid());

-- categories
alter table categories enable row level security;

create policy "select own categories"
on categories for select
using (user_id = auth.uid());

create policy "insert own categories"
on categories for insert
with check (user_id = auth.uid());

create policy "update own categories"
on categories for update
using (user_id = auth.uid());

create policy "delete own categories"
on categories for delete
using (user_id = auth.uid());

-- routine_items
alter table routine_items enable row level security;

create policy "select own or shared with partner"
on routine_items for select
using (
  user_id = auth.uid()
  or (is_shared = true and user_id = partner_id(auth.uid()))
);

create policy "insert own items"
on routine_items for insert
with check (user_id = auth.uid());

create policy "update own or shared items"
on routine_items for update
using (
  user_id = auth.uid()
  or (is_shared = true and user_id = partner_id(auth.uid()))
);

create policy "delete own or shared items"
on routine_items for delete
using (
  user_id = auth.uid()
  or (is_shared = true and user_id = partner_id(auth.uid()))
);

-- item_completions
alter table item_completions enable row level security;

create policy "select own or shared item completions"
on item_completions for select
using (
  user_id = auth.uid()
  or exists (
    select 1 from routine_items ri
    where ri.id = item_completions.routine_item_id
      and ri.is_shared = true
      and (ri.user_id = auth.uid() or ri.user_id = partner_id(auth.uid()))
  )
);

create policy "insert own completions"
on item_completions for insert
with check (user_id = auth.uid());

create policy "delete own completions"
on item_completions for delete
using (user_id = auth.uid());

-- push_subscriptions
alter table push_subscriptions enable row level security;

create policy "manage own subscriptions"
on push_subscriptions for all
using (user_id = auth.uid())
with check (user_id = auth.uid());
```

```ts
import { createClient } from '@supabase/supabase-js'
import { describe, it, expect, beforeAll } from 'vitest'

const url = process.env.SUPABASE_URL!
const anonKey = process.env.SUPABASE_ANON_KEY!

async function signUp(email: string, password: string) {
  const client = createClient(url, anonKey)
  const { data, error } = await client.auth.signUp({ email, password })
  if (error) throw error
  return { client, userId: data.user!.id }
}

describe('routine_items RLS', () => {
  it('user A cannot see user B personal item', async () => {
    const a = await signUp('a-rls@test.com', 'password123')
    const b = await signUp('b-rls@test.com', 'password123')

    const { data: category } = await b.client
      .from('categories')
      .insert({ user_id: b.userId, nome: 'Estudos', cor: '#000', icone: 'book' })
      .select()
      .single()

    await b.client.from('routine_items').insert({
      user_id: b.userId,
      category_id: category!.id,
      titulo: 'Item pessoal de B',
      data_inicio: '2026-08-12',
      horario: '09:00',
      is_shared: false,
    })

    const { data: seenByA } = await a.client.from('routine_items').select('*')
    expect(seenByA).toEqual([])
  })

  it('partner can see and edit a shared item', async () => {
    const code = `code-${Date.now()}`
    const a = await signUp(`a-shared-${Date.now()}@test.com`, 'password123')
    const b = await signUp(`b-shared-${Date.now()}@test.com`, 'password123')

    await a.client.from('couples').insert({ code, user_a: a.userId })
    await b.client.from('couples').update({ user_b: b.userId }).eq('code', code)

    const { data: category } = await a.client
      .from('categories')
      .insert({ user_id: a.userId, nome: 'Treino', cor: '#000', icone: 'dumbbell' })
      .select()
      .single()

    const { data: item } = await a.client
      .from('routine_items')
      .insert({
        user_id: a.userId,
        category_id: category!.id,
        titulo: 'Academia juntos',
        data_inicio: '2026-08-12',
        horario: '18:00',
        is_shared: true,
      })
      .select()
      .single()

    const { data: seenByB } = await b.client.from('routine_items').select('*').eq('id', item!.id)
    expect(seenByB).toHaveLength(1)

    const { error: updateError } = await b.client
      .from('routine_items')
      .update({ titulo: 'Academia juntos (editado por B)' })
      .eq('id', item!.id)
    expect(updateError).toBeNull()
  })
})
```

- [ ] **Step 4: Implement `AuthContext`**

`src/features/auth/AuthContext.tsx`:

```tsx
import { createContext, useContext, useEffect, useState, type ReactNode } from 'react'
import type { User } from '@supabase/supabase-js'
import { supabase } from '../../lib/supabaseClient'

type AuthState = { user: User | null; loading: boolean }

const AuthContext = createContext<AuthState>({ user: null, loading: true })

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    supabase.auth.getSession().then(({ data }) => {
      setUser(data.session?.user ?? null)
      setLoading(false)
    })

    const { data: listener } = supabase.auth.onAuthStateChange((_event, session) => {
      setUser(session?.user ?? null)
    })

    return () => listener.subscription.unsubscribe()
  }, [])

  return <AuthContext.Provider value={{ user, loading }}>{children}</AuthContext.Provider>
}

export function useAuth() {
  return useContext(AuthContext)
}
```

```ts
import { supabase } from '../../lib/supabaseClient'

function generateCode(): string {
  return Math.random().toString(36).slice(2, 8).toUpperCase()
}

export async function createCouple(userId: string): Promise<{ code: string }> {
  const code = generateCode()
  const { data, error } = await supabase
    .from('couples')
    .insert({ user_a: userId, code })
    .select('code')
    .single()
  if (error) throw error
  return { code: data.code }
}

export async function joinCouple(userId: string, code: string): Promise<void> {
  const { error } = await supabase
    .from('couples')
    .update({ user_b: userId })
    .eq('code', code)
  if (error) throw error
}
```

```tsx
import { useState } from 'react'
import { useNavigate } from 'react-router-dom'
import { useAuth } from '../auth/AuthContext'
import { createCouple, joinCouple } from './coupleApi'

export default function CoupleSetupPage() {
  const { user } = useAuth()
  const [generatedCode, setGeneratedCode] = useState<string | null>(null)
  const [joinCode, setJoinCode] = useState('')
  const [error, setError] = useState<string | null>(null)
  const navigate = useNavigate()

  async function handleCreate() {
    if (!user) return
    setError(null)
    try {
      const { code } = await createCouple(user.id)
      setGeneratedCode(code)
    } catch (e) {
      setError((e as Error).message)
    }
  }

  async function handleJoin() {
    if (!user) return
    setError(null)
    try {
      await joinCouple(user.id, joinCode.trim().toUpperCase())
      navigate('/')
    } catch (e) {
      setError((e as Error).message)
    }
  }

  return (
    <div>
      <h1>Conectar com seu par</h1>
      <section>
        <button onClick={handleCreate}>Criar código de casal</button>
        {generatedCode && <p>Compartilhe este código: {generatedCode}</p>}
      </section>
      <section>
        <input
          placeholder="Código recebido"
          value={joinCode}
          onChange={(e) => setJoinCode(e.target.value)}
        />
        <button onClick={handleJoin}>Entrar com código</button>
      </section>
      {error && <p role="alert">{error}</p>}
    </div>
  )
}
```

## Known gaps carried into Plan 2

Flagged by the final whole-branch review after Plan 1 completed; both accepted as deliberate scope decisions rather than fixed in Plan 1.

- **Default categories (Global Constraint) not implemented.** New accounts get zero categories today — no task in this plan seeds the 4 defaults (Treino/Saúde, Estudos, Trabalho, Lazer). Plan 2 (Categories & Routine Items CRUD) must include this, either as a DB trigger on `auth.users` or client-side seeding right after signup/couple-setup.
- **`couples` RLS is more permissive than the UI implies.** The `select own or joinable couples` policy exposes every row with `user_b is null` (code + `user_a` id) to any authenticated user, and `join couple` lets anyone set themselves as `user_b` on any open couple — the client only filters by code, RLS doesn't enforce it. Accepted for now since this is a 2-person app with no adversarial users; revisit (e.g. move the join through a `SECURITY DEFINER` RPC that checks the code server-side) if the product ever opens beyond a single trusted couple per deploy.
